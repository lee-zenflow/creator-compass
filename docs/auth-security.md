# 身份安全说明（Task 3）

## 当前实现

- Better Auth 1.6.26 的 `user`、`session`、`account`、`verification` 是正式账号的唯一事实源，数据库 ID 使用 UUID。
- 游客 Cookie 使用 32 字节随机值；数据库只保存 SHA-256，Cookie 为 HttpOnly、SameSite=Lax、Path=/，生产环境开启 Secure，30 天过期。
- 游客合并只接受服务端会话和 Cookie。它会锁定游客会话、延期全部约束、检查正式账号已验证且 active，再在同一事务迁移全部归属表。
- `creator_profiles` 与 `user_settings` 冲突时保留正式账号值，游客值写入 `guest_draft` 并标记 `guest_conflict`，不静默覆盖。
- 登录、注册、重置与重发使用 Better Auth 自带的来源校验和账号枚举保护；自定义游客接口额外强制校验 Origin。
- 生产认证限流已显式启用。反向代理部署必须把真实代理 IP/CIDR 写入 `AUTH_TRUSTED_PROXIES`，否则不要信任转发头。

## Better Auth 1.6.26 的令牌语义

设计稿要求“验证和重置令牌短时、单次、数据库只存哈希”。保持 Better Auth 标准表和标准端点时，1.6.26 的真实行为是：

- 邮箱验证令牌是短时签名令牌，不写数据库；验证成功后不能再次产生有效状态变化。
- 密码重置使用短时随机令牌，标准 `verification` 表保存它的标识并在成功使用后删除，但该标识不是哈希值。

本任务没有私自改写库的加密或查询逻辑，因为那会造成与后续升级不兼容的第二套认证实现。若发布门槛必须严格满足“重置令牌只存哈希”，应在发布前选择支持哈希令牌的 Better Auth 版本，或单独安排经过安全审计的适配器；当前实现应视为一项已知规格差异。

## 本地验证边界

本机没有可用 Docker/PostgreSQL 服务，因此本任务运行了注入式事务仓储测试，覆盖全表迁移、冲突保留、幂等、过期拒绝与失败回滚；未声称真实 PostgreSQL 集成已运行。迁移文件包含延期复合外键和游客审计外键 `ON DELETE RESTRICT`，部署环境仍需执行数据库集成测试。
