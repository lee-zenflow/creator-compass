# Creator Compass「指南针仪表」全产品优化设计规格

日期：2026-08-13

状态：待用户最终审阅
适用范围：Creator Compass 用户端、知识库后台及其共用视觉系统

## 1. 背景与目标

Creator Compass 已具备可运行的「IP 定位 → 事前创作 → 数据复盘 → 下一轮任务」闭环、任务与素材管理、报告记录、账号合并、AI 任务和 RAG 知识库。本轮不是重做信息架构，也不横向堆叠功能，而是在现有 Figma 框架上完成一次全产品统一优化。

本轮解决四个问题：

1. 页面虽然紧凑，但等宽白卡片、通用图标底座和平均分配的层级仍有明显模板感。
2. 关键操作、AI 状态、证据来源和失败恢复还需要更接近真实可长期使用的 App。
3. 定位、创作、复盘、任务、素材和报告之间需要统一的视觉语言与连续的行动导航。
4. RAG 的来源、审核、引用和无命中状态必须在用户端和后台形成真实、可追溯的展示。

本轮目标：保留 Figma 的手机比例、页面顺序和核心交互，把产品升级为具有独立品牌记忆、真实状态、完整异常处理和统一模块识别的移动端应用。

## 2. 已确认的设计方向

主视觉选择「指南针仪表」，局部结合「数据脉冲」。

本规格是现有 A→B→C 优化设计的视觉与全页面深化版本：继续沿用 A 的真实路径与失败恢复、C 的 RAG 生产闸门；若与旧规格的 B 阶段视觉表述不同，以本规格为准。它不改变已稳定的业务安全约束。

- 「指南针仪表」用于全产品骨架：罗盘刻度、方向标识、坐标编号、行动轨迹、细网格和局部深色行动块。
- 「数据脉冲」仅用于 AI 处理状态、数据复盘指标和关键生成结果，不扩散到访谈、表单和设置页。
- 保留现有 Figma 的信息架构、手机比例、紧凑列表和单手操作逻辑。
- 不使用常见紫蓝 AI 渐变、模板化 Bento、大面积发光、大圆角玻璃卡和无法解释的装饰数据。

## 3. 设计原则与边界

### 3.1 必须保持

- 用户端以 390×844 为基准，同时适配 360×800 与 412×915。
- 底部四项导航、二级页面顶部返回和现有业务路径不变。
- 列表行约 56–64px；候选摘要约 130–148px；任务约 76–84px；主要控件约 42px。
- 用户端在桌面宽屏保持手机画板比例，不横向拉成扁平仪表盘；管理后台继续使用独立桌面布局。
- 所有业务结果必须来自真实数据库、AI run 或检索记录。

### 3.2 明确禁止

- 自动增长的 AI 百分比、虚假预计完成时间、假趋势、假案例和伪造引用。
- 无法说明计算方法的匹配度、准确率或成功概率。
- 为追求视觉效果而放大每个模块、降低信息密度或把长正文塞进列表卡片。
- 为本轮视觉优化新增第二套业务状态机、重型动画依赖、向量数据库或独立微服务。
- 未经来源和切片双重审核的资料进入生产检索。

## 4. 统一视觉系统

### 4.1 色彩

- 基础背景：暖灰白，降低纯白页面的模板感。
- 主文字：深海军蓝，承担标题、导航和结构线。
- 品牌强调：冷青绿，承担方向、选中状态、轨迹节点和可执行入口。
- 局部深色：深海军蓝或近黑蓝，仅用于当前行动、AI 处理和复盘关键结果。
- 辅助色：定位使用浅青、创作使用雾蓝、复盘使用浅沙金；只用于小图标、细边、标签和来源标识。
- 错误色：低饱和红，仅用于失败、风险和危险操作。

所有颜色必须满足正文、按钮和交互状态的可读性要求；不能仅依赖颜色表达状态。

### 4.2 图形语言

- 每个一级功能、报告类型、任务来源和后台菜单使用统一的 18px 线性图标，默认线宽约 1.8。
- 定位、创作、复盘、任务和素材分别拥有稳定图形符号，不使用随机星星、魔法棒等泛 AI 图标。
- 页面结构可使用罗盘圆弧、方位刻度、坐标编号和行动轨迹线，但不得覆盖正文或影响点击。
- 当前行动区允许使用局部深色底和坐标编号，形成主视觉记忆。

### 4.3 卡片与层级

- 减少等宽、等高、等权重的大白卡，优先使用分隔线、错位层级、编号和局部底色。
- 列表页面保留紧凑行；详情页面使用正文段落、标题层级和细分隔线。
- 列表正文最多两行，超出省略；完整信息进入详情页。
- 圆角以 6px、8px 为主，只有明确的浮层或主行动区可使用更大圆角。
- 阴影仅用于浮层和底部抽屉，不给普通列表卡增加厚阴影。

### 4.4 排版

- 中文正文使用系统无衬线字体，保持移动端稳定渲染。
- 坐标、序号、日期和数据可使用等宽数字或 tabular numbers，形成仪表感。
- 标题不使用超大营销字号；页面标题、区块标题、正文和辅助说明形成四级稳定层级。
- 英文只作为短坐标或状态辅助，不替代中文核心信息。

### 4.5 动效

- 页面进入、导航选中、任务完成和状态切换控制在 160–220ms。
- 当前行动可使用轻微轨迹推进；AI 处理中可使用缓慢罗盘扫描；指标只在存在真实历史时绘制趋势变化。
- 动效优先使用 opacity 与 transform，避免影响布局和低端手机性能。
- `prefers-reduced-motion: reduce` 时关闭非必要动效。

## 5. 用户端页面改造

### 5.1 欢迎、登录与注册

- 欢迎页只保留产品定位、真实核心闭环和一个主要入口，不堆叠宣传卡片。
- 手机验证码、邮箱登录、注册、验证、密码找回和游客体验使用统一 42px 控件与清晰错误说明。
- 游客转注册后自动合并定位、任务、素材和报告；合并失败必须可恢复且不删除游客数据。
- 不在验证、发送邮件或登录失败时用假成功掩盖真实错误。

### 5.2 工作台

- 顶部显示当前创作阶段与位置坐标。
- 首屏只突出一个「下一步行动」，包含状态、来源版本、预计投入时间（仅用户或任务真实填写）和真实入口。
- 展示进行中、待复盘和画像完整度三个真实指标。
- 最近任务最多两条，最近报告使用紧凑时间线。
- 趋势线仅在存在足够真实记录时显示；空数据使用解释性空状态。

### 5.3 工具箱

- 保留 IP 定位、事前创作、数据复盘、素材库、报告记录五个入口。
- 每个入口展示独立图标、短说明、最近更新时间和真实状态。
- 使用工具目录或分组列表，避免五张同权重大卡。
- 页面强化「定位 → 创作 → 复盘 → 下一轮」的行动轨迹。

### 5.4 IP 定位

- 定位记录展示状态、画像完整度、最后更新时间和继续入口。
- AI 访谈顶部展示八维画像完整度；最多十轮后必须提供手动补齐入口，不能形成死路。
- 80% 与 100% 提示只出现一次，并由真实完整度驱动。
- 报告生成阶段只展示持久化的真实状态，不把未开始的检索标成完成。
- 三项候选摘要只展示定位名称、目标人群、内容方向和推荐理由摘要。
- 详情页展示完整依据和可读引用；没有知识命中时写明「仅基于本次访谈信息，暂无匹配案例依据」。
- 用户确认候选后新增定位报告版本和创作档案版本，不覆盖历史。
- 确认后的任务预览只允许选择已确认候选的任务，重复提交不产生重复任务。

### 5.5 事前创作

- 创作需求按目标、平台、内容类型、补充要求分步输入，不在首屏展示完整大表单。
- 可选择素材库内容或上传本地素材；引用关系可追溯。
- AI 输出内容主题、标题建议、内容结构、发布建议和执行任务。
- 方案可编辑、重新生成或确认；确认生成新版本。
- 任务写入只接受当前方案中的合法任务，并保持幂等。
- 无 RAG 命中时明确标注仅基于用户输入与个人档案生成。

### 5.6 数据复盘

- 支持平台授权读取、手动填写和截图 OCR 三种路径。
- OCR 原始结果必须由用户确认后才能形成指标快照。
- 报告固定为数据摘要、值得保留、存在问题、原因判断和下一轮行动。
- 关键指标区使用局部「数据脉冲」视觉；不存在真实对比期时不画趋势。
- 行动建议可写入任务中心，并记录来源报告和版本。

### 5.7 任务中心

- 提供今日、本周、全部筛选。
- 每条任务显示定位、创作或复盘来源图标、完成标准、计划日期和优先级。
- 支持完成、恢复、编辑、删除和调整顺序。
- 任务详情展示「为什么做」、执行步骤、来源报告和返回报告入口。
- 同一来源版本和任务标识只能写入一次；重复选择只能补充缺失任务。

### 5.8 素材库与报告记录

- 素材列表默认紧凑展示，新建和编辑使用底部抽屉。
- 素材展示名称、类型、来源、最近关联内容和保存时间。
- 活跃方案引用的素材不得静默删除；必须提示影响并要求解除引用。
- 报告记录分为定位、创作和复盘，显示真实状态、更新时间与来源图标。
- 报告详情展示版本关系、生成模式、真实引用和生成失败恢复入口。

### 5.9 我的与设置

- 个人创作档案展示当前定位、用户条件、内容方向、平台偏好、素材沉淀和最近复盘结论。
- 手动修改档案产生新版本，不覆盖历史。
- 提供平台授权、任务与报告提醒、隐私、账号安全、套餐和协议入口。
- 未实现的套餐或第三方平台能力不得伪装成已接入。

## 6. AI 状态与失败恢复

### 6.1 用户可见状态

允许展示的状态：

1. 输入已保存。
2. 等待处理。
3. 正在检索已审核资料。
4. 正在生成结构化方案。
5. 结果校验中。
6. 已完成或生成失败。

只有后端真实持久化对应阶段时，界面才能声明该阶段正在进行或已经完成。若基础设施只有整体 `processing`，界面只能显示「正在处理」，不能伪造阶段拆解。

### 6.2 恢复原则

- 失败后保留原输入和业务草稿。
- 重试要么重新排队同一合法失败 run，要么创建明确关联的新 attempt；不能把旧 failed run 冒充 processing。
- 异步终态失败必须释放对应业务锁。
- 同一幂等键重复操作返回同一活动结果；内容变化时返回冲突或创建新版本。
- UI 只展示固定安全错误码对应的可理解文案，不展示模型原文、内部 IP、对象键或密钥。

## 7. RAG 知识库与证据

### 7.1 入库范围

- 支持安全网页抓取、TXT、PDF、DOCX 和手动文本。
- 文件和正文执行大小、页数、字符数、MIME、压缩包和 SSRF 安全校验。
- 内容经过正文提取、中文确定性切片、候选标签生成和私有存储归档。

### 7.2 生产闸门

- 来源审核与切片审核分离。
- 只有来源已通过、切片已通过、production scope、非 Demo 且启用的内容才能被生产检索。
- 审核记录追加保存审核人、前后状态、理由和时间。
- AI 可提出标签与摘要候选，但不能完成审核。

### 7.3 检索与引用

- 使用现有 PostgreSQL 中文 substring、trigram、full text 和标签信号混合检索。
- 同一来源最多占最终结果的三条，避免单一长文档垄断证据。
- 用户报告只能引用本次 retrieval snapshot 中实际存在的 itemId/sourceId 组合。
- 用户端显示资料标题、来源类型、短摘要与审核属性，不显示内部 UUID。
- 没有命中时允许基于用户输入生成，但必须明确无案例依据。

### 7.4 管理后台

- 知识首页展示来源总数、待处理、待审核、生产可用、停用、失败和切片审核进度。
- 来源详情展示解析信息、切片、审核历史和失败原因。
- 检索实验室展示前八条结果、命中信号、过滤原因和来源多样性。
- 异常任务区支持受控重试；永久性安全错误要求重新提交。
- 演示案例、内部示例和待审核资料默认排除生产检索。

## 8. 交互、内容与无障碍

### 8.1 交互

- 一级页面使用底部导航，二级页面使用顶部返回。
- 新建、筛选和轻量编辑优先使用底部抽屉。
- 关键确认操作固定在底部；次要操作放进更多菜单。
- 所有点击区域不小于 42px，支持键盘焦点与屏幕阅读器标签。

### 8.2 文案

每个页面按「当前状态 → 为什么 → 下一步做什么」组织。

- 不写「AI 为你赋能创作」，改为「确认方向后，生成下一轮可执行任务」。
- 不写「正在进行智能分析」，改为真实的「正在检索已审核资料」或「正在处理」。
- 不展示无法解释的「匹配度 92%」，改为说明符合哪些用户条件。
- 错误文案必须说明数据是否已保存和用户下一步可以做什么。

### 8.3 空状态

- 没有任务：引导从定位、创作或复盘生成第一条任务。
- 没有知识命中：说明只依据本次输入生成。
- 授权失败：保留手动填写和 OCR 路径。
- AI 未配置：明确配置问题，不返回假结果。
- 网络中断：保存草稿并说明恢复状态。

## 9. 数据与组件边界

- 页面展示只消费现有服务或新增的只读展示模型，不在组件内重新实现业务判断。
- 当前行动由真实业务聚合状态推导，不新增容易漂移的 `currentStage` 真值字段。
- AI 状态、检索记录、报告版本、任务来源和档案版本继续由数据库持久化并校验 owner。
- 共用视觉组件只负责展示：`ModuleIcon`、`StatusRow`、`MetricSparkline`、`CompactRecordRow`、`EvidenceList`、`AiRunStatus`、`BottomSheet`。
- 定位、创作、复盘服务继续拥有业务写入职责；RAG 服务继续拥有入库、审核、检索和引用校验职责。

## 10. 实施顺序

为避免一次大改导致业务回归，按以下顺序实施并分别验证：

1. 视觉令牌、图标映射、移动画板、基础列表、按钮、抽屉和动效。
2. 工作台、工具箱、底部导航、我的与设置。
3. IP 定位全链路与真实 AI 状态。
4. 事前创作全链路与任务写入。
5. 数据复盘、OCR 确认与行动任务。
6. 任务、素材、报告详情与来源追溯。
7. RAG 后台、审核历史、检索解释和用户可读引用。
8. 移动端视觉回归、完整 E2E、健康检查、发布验证和部署。

每一步必须保持已有业务可运行，不能以视觉占位替代真实功能。

## 11. 验收标准

### 11.1 视觉与移动端

- 360×800、390×844、412×915 均无横向溢出、底栏遮挡和异常大卡。
- 用户端在桌面宽屏保持手机比例；后台适配桌面宽屏。
- 长候选、长任务和长报告不会撑破列表，完整内容可在详情查看。
- 五个工具入口、三类报告、三类任务来源和后台菜单均有稳定图标。
- 不出现紫蓝 AI 渐变、大面积玻璃卡、假数据装饰或无意义发光。

### 11.2 功能

- 游客可完整走通定位、定位任务、创作、创作任务、复盘、改进任务、注册、邮箱验证、登录与数据合并。
- 三类报告、任务来源、素材引用、档案版本和引用证据都能真实追溯。
- 定位、创作、复盘 AI 失败后可从保存内容恢复。
- OCR 指标只在用户确认后写入。
- 同一报告任务重复提交不产生重复任务。

### 11.3 RAG 与安全

- SSRF、文件超限、不支持 MIME、不安全 DOCX 和空正文被安全拒绝。
- 来源和切片双审核、非 Demo、production 和 enabled 闸门同时生效。
- 引用严格属于本次检索；无命中明确提示。
- 审核人、审核原因、状态变化和时间可查询。
- 日志和页面不泄露密钥、内部网络、私有对象地址和完整私密输入。

### 11.4 工程与发布

- 单元、服务、迁移和 E2E 测试通过。
- 类型检查、代码规范、生产构建和数据库迁移检查通过。
- 隔离测试库从零迁移、种子和完整 E2E 通过，不能复用开发或生产数据库。
- 发布前健康检查覆盖数据库、对象存储、Web 与 worker。
- GitHub 开源前确认无 `.env.local`、API 密钥、邮件凭据、对象存储凭据、测试数据和本地生成缓存进入版本库。

## 12. 非目标

- 本轮不增加社交发布、商业支付、团队协作、自动代理运营或新的第三方平台承诺。
- 本轮不把管理后台做成另一套营销型产品。
- 本轮不为视觉效果重写已稳定的数据模型和 AI 基础设施。
- 本轮不承诺外部平台无法提供的实时数据接口。

## 13. 成功判断

完成后，用户应能在任何页面快速回答三个问题：

1. 我现在处于创作闭环的哪一步？
2. 当前结果来自什么真实输入、数据或知识依据？
3. 下一步可以执行什么动作，失败后如何继续？

视觉上，产品应保留原 Figma 的紧凑手机框架，同时通过罗盘、坐标、轨迹、局部深色操作区和真实数据线形成独立的 Creator Compass 品牌，而不是另一套通用 AI SaaS 模板。
