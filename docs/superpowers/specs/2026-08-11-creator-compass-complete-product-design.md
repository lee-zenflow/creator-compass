# Creator Compass 完整产品深化设计

日期：2026-08-11

## 1. 目标

在现有可运行的 Creator Compass 基础上完成一次全产品深化，而不是重建新项目。最终产品要把「0-1 IP 定位 → 事前创作 → 发布后数据复盘 → 下一轮任务」做成可恢复、可核验、可持续使用的手机端闭环，并提供独立桌面运营后台维护 RAG 知识、提示词、平台规则、AI 任务和异常。

本次同时解决三个问题：

- 视觉过于平、信息层级弱，但不能通过放大卡片和增加大留白来解决。
- 功能虽已覆盖主流程，但部分页面、状态、后台维护和跨模块承接仍不够完整。
- RAG 已有审核、全文检索和引用基础，但缺少完整的资料获取、解析、切片、审核、检索试验和运营界面。

## 2. 设计依据与事实边界

### 2.1 设计与需求来源

- `1111.fig`：手机端页面造型、390×844 画板、紧凑列表、顶栏、底栏和核心流程参考。
- `作品集_产品流程讲解_可编辑版.fig`、产品流程图和功能结构图：定位、创作、复盘、任务和后台模块边界。
- `迭代作业.docx`：V1 内容生成与基础复盘、V2 数据接入与知识库、V3 0-1 IP 定位的版本逻辑。
- `数据看板方案.docx`：近 3/7/30 天周期、播放或曝光、互动率、涨粉和复盘报告结构。
- `数据埋点.docx`：定位确认率、任务保存率、复盘行动转化率、任务完成率和数据获取完成情况。
- `用户画像调研.docx`：定位探索型、创作卡壳型和复盘迷茫型三类核心用户。
- `竞品分析.pdf`、作品集和简历：产品定位、竞品差异和项目真实性口径。
- `全部课程逐字稿.docx`：技术机制与课程建议参考，不作为正式知识案例或用户研究证据。

### 2.2 真实性边界

- 不把课程示例、作品集演示页面、内部 Demo 或无法核验的账号结果包装成真实案例。
- 生产 RAG 只使用来源与内容均审核通过、非 Demo、生产范围内的资料。
- 平台规则只有在可核验官方来源存在时才标记为官方；内部分析规则必须显示其内部属性。
- 没有 RAG 命中时，产品明确显示「仅基于用户资料，暂无匹配案例依据」。
- 页面指标、审核数量和运营结果全部读取数据库；空数据展示空状态或破折号，不填演示数字。
- 作品集、简历和课程逐字稿只用于提炼产品需求，不直接作为产品页面或生产知识导入。

## 3. 总体架构

产品采用「一个业务闭环，两种界面，共享一套底座」。

### 3.1 手机用户前台

以 390×844 为主画板，适配 360–430px 手机宽度。保留四个底部导航：

1. 工作台：账号、周期数据、最新判断、未来三天行动、最近报告和闭环进度。
2. 工具箱：IP 定位、事前创作、数据复盘、素材库和报告记录。
3. 任务：今日、本周、全部任务，支持查看、编辑、完成和删除。
4. 我的：个人 IP 档案、平台账号、提醒、数据导出、身份和隐私设置。

### 3.2 桌面运营后台

后台以 1280/1440px 桌面宽度为主，不把批量资料管理压缩进手机界面。后台包含：

- 知识来源、内容切片、审核队列和检索试验台。
- 平台规则、提示词版本、AI 任务和异常任务。
- 用户与授权、最小运营看板和数据导出。

### 3.3 共享底座

- Better Auth 注册用户与 30 天游客身份。
- PostgreSQL 聚合根、版本记录、用户归属和幂等约束。
- DeepSeek 结构化生成、Zod 校验、pg-boss 任务和失败状态。
- MinIO 私有对象存储与浏览器本地 OCR。
- 审核知识检索、召回快照、报告引用和任务来源追踪。

## 4. 手机前台信息架构与功能

### 4.1 工作台

工作台首屏按以下顺序展示：

1. 当前平台账号与切换入口。
2. 近 3/7/30 天周期切换。
3. 播放或曝光、互动率、涨粉量或涨粉转化三项真实指标。
4. 轻量趋势图；数据不足时显示所需样本条件。
5. 最新判断：把指标变化翻译成可理解结论。
6. 未来三天行动：最多显示两条高优先级任务。
7. 最近报告和当前闭环位置。

工作台不重复工具箱入口，不显示大面积欢迎卡，也不填充模拟数据。

### 4.2 0-1 IP 定位

流程为：定位记录 → AI 访谈 → 画像完整度 → 生成状态 → 三个候选 → 候选详情 → 用户确认 → 任务预览 → 写入个人档案。

- 访谈最多十轮，围绕兴趣与经历、能力与资源、可投入时间、创作目标、平台偏好和持续内容来源收集证据。
- 完整度来自已确认画像维度，不由前端定时增长。
- 达到可生成条件后由用户选择生成；100% 时不继续提出核心问题。
- 三候选列表只显示名称、目标人群、内容方向和匹配摘要；完整理由、风险、引用和首轮任务进入详情页。
- 候选引用必须属于本次检索快照；无命中允许生成，但不得伪造案例。
- 用户确认后追加不可变手工报告版本和个人档案版本，再生成可选择的行动任务。

### 4.3 事前创作

流程为：填写需求 → 选择个人素材 → 读取定位与历史 → 检索审核知识 → 生成方案 → 用户调整 → 生成执行任务。

- 创作需求包含内容类型、目标、平台和补充要求。
- 素材选择使用紧凑列表，新增素材表单按需展开，不常驻首屏。
- 方案包含内容主题、标题建议、内容结构、发布建议和必要初稿。
- 方案清楚区分用户素材、个人档案、历史结论和公共知识依据。
- 写入任务时保存方案版本、选择顺序和最小来源快照，避免重复任务。

### 4.4 数据复盘

流程为：选择平台与已发内容 → 选择数据来源 → 平台数据或截图 OCR → 用户确认字段 → 生成报告 → 用户调整 → 生成下一轮任务。

- OCR 在浏览器本地执行，原图默认不上传；用户显式保存截图时才写入私有对象存储。
- 用户必须确认识别后的字段，报告不直接使用未确认 OCR 结果。
- 报告按「综合表现 → 历史对比 → 指标拆解 → 问题诊断 → 行动建议 → 分析依据」展示。
- 平台不提供曝光时不估算；涨粉归因使用近似值时必须标注。
- 样本少于三条时不做强历史结论。
- 复盘任务带回具体选题、标题钩子、开头、结构或关注理由，而不是抽象的“继续优化”。

### 4.5 任务、素材、报告与档案

- 任务支持今日、本周、全部，包含名称、来源、为什么做、执行步骤、计划日期、预计时长、优先级、完成标准和状态。
- 素材包含摘要、类型、正文、来源、关联历史内容、保存时间和是否被活跃项目引用。
- 报告按定位、创作和复盘分类，显示状态、版本、短摘要与真实详情链接。
- 个人档案保存当前定位、八维画像、平台偏好、内容方向、最近复盘结论和素材沉淀；所有手工编辑追加版本。

## 5. 视觉系统

### 5.1 总体方向

采用已确认的「原 Figma 深化版」：保留黑白灰、细边框、紧凑布局和居中手机画板，加入低饱和青色、浅层背景、小型图表、状态色和轻量动效。丰富感来自信息和状态，不来自大卡片、大渐变、厚阴影或装饰插画。

### 5.2 核心视觉令牌

- 页面背景：`#F4F7F6`；主表面：`#FFFFFF`。
- 主文字：`#17252B`；次文字：`#5F7177`；弱文字：`#718086`。
- 主交互：`#397E83`；深色强调：`#223F49`；浅青表面：`#E7F0F1`。
- 分隔线：`#D9E3E4`；成功、审核、异常只使用低饱和语义色。
- 中文字体继续使用系统中文字体栈；数字启用等宽数字。
- 页面左右边距 15px；模块间距 6–10px。
- 顶栏 48px；底部导航 62px；固定操作区 56px；主按钮 42px。
- 普通列表 48–64px；任务卡约 84px；定位候选约 148px。
- 外层圆角 8–10px；内层圆角 4–6px。
- 交互动效 160–220ms，只使用透明度和轻位移，并支持减少动态偏好。

### 5.3 图标系统

- 每个一级功能、模块入口、任务来源、报告类型和后台菜单都有图标。
- 使用项目现有 `lucide-react` 图标，统一 18px、约 1.8px 描边和 36px 小圆角底座，不新增第二套图标库。
- 墨青色表示主交互；蓝色表示数据；金色表示审核或提醒；红色只表示异常和危险操作。
- 普通说明文字和单纯数值不滥用图标。
- 图标必须配文字标签，不以图标单独表达关键业务操作。

### 5.4 内容密度与状态

- 列表摘要最多两行，完整 AI 长文本进入详情页。
- 页面每次只突出一个主操作，次要操作使用轻按钮或文字入口。
- 提供与页面结构匹配的骨架加载、真实处理中、空状态、就近表单错误和可恢复失败状态。
- AI 处理中只显示可确认事实，不展示模型尚未完成的虚假阶段或预计时间。
- 所有可点击元素有按压、键盘焦点和禁用状态。

## 6. RAG 知识库设计

### 6.1 首期检索策略

首期使用 PostgreSQL 本地混合检索，不增加新的付费向量服务。检索同时使用结构化标签、`pg_trgm` 中文相似度或子串匹配，以及现有 `to_tsvector('simple')` 对空格词组和英文内容的全文排名。这样既能复用现有 `knowledge_sources`、`knowledge_items`、`platform_rules`、`retrieval_records` 和生产审核闸门，也能避免连续中文仅依赖 `simple` 分词而漏召回。

未来只有在获得稳定的 embedding 服务、建立离线评测集并证明语义召回优于现有方案后，才增加向量排序；向量只作为混合排序信号，不替代来源审核和引用校验。

### 6.2 资料类型

- 真实案例：需要可核验公开来源和明确捕获时间。
- 内容模式：选题、标题、结构、表达、适合人群和避坑点。
- 平台规则：记录来源、有效期、权威性和是否官方。
- 内部示例：只用于开发测试，固定为 `development_only`，不得进入生产检索。

### 6.3 入库流程

1. 管理员提交公开 URL、PDF/DOCX/TXT 文件或手动文本。
2. 系统校验来源类型、授权范围和输入大小；单个文件最大 10 MiB。
3. URL 获取仅允许 HTTP/HTTPS，阻止环回、私网、链路本地和云元数据地址；DNS 解析后再次校验最终 IP，最多跟随 3 次重定向，每次重定向重新校验；请求超时 15 秒，响应正文最大 8 MiB。
4. URL 和文件只接受 HTML、纯文本、PDF 与 DOCX；文件保存到私有对象存储，校验 MIME、扩展名和大小，解析器不执行宏、脚本或嵌入对象。
5. 系统提取正文、规范化空白、计算内容哈希并去重。
6. 按标题和段落边界切分；目标每片 600 个字符、最少 300、最多 800，超长段落使用固定 100 字符重叠，并保存切片序号和字符范围。
7. DeepSeek 只生成结构化摘要、关键词和候选标签，不决定审核结果。
8. 来源和切片进入待审核状态；管理员可编辑、通过、拒绝或停用。
9. 来源与内容同时审核通过、非 Demo 且范围为 production 后才可检索。

### 6.4 检索与生成

1. 根据用户定位、平台、内容类型和当前任务形成受控过滤条件、规范化关键词和确定性的 `searchable_text`。
2. SQL 先执行生产闸门、平台和内容类型过滤，再组合精确标签命中、中文 trigram 相似度或子串命中、全文排名、内容权重和稳定 ID 次序进行排序。
3. 平台规则允许 `all` 作为全平台规则；知识案例必须匹配目标平台和内容类型。
4. 单次最多召回 8 条，限制同一来源占比，并保留 item ID、source ID、版本、哈希、排名和得分。
5. DeepSeek 只接收截断后的可信片段和明确的不可信用户输入边界。
6. 持久化前校验引用的 item/source 组合确实存在于本次召回快照。
7. 无命中时允许基于用户资料生成，但输出必须显示「暂无匹配案例依据」。

### 6.5 后台页面

- 知识概览：真实来源数、待审核数、生产可用数、失败数和检索使用情况。
- 来源列表与详情：来源、抓取状态、内容哈希、版本、授权、审核和关联切片。
- 切片列表与编辑：标题、正文、摘要、标签、平台、内容类型和结构化结论。
- 审核队列：来源与内容分开审核，支持通过、拒绝、停用和原因记录。
- 检索试验台：输入平台、内容类型、标签和关键词，显示命中片段、排序、过滤原因和引用信息。
- 平台规则：来源、有效期、权威性、官方标识、生产范围和启停状态。
- AI 任务与异常：安全状态、错误码、重试、耗时、模型、提示词版本和检索记录，不暴露私密输入。

## 7. 数据模型调整原则

保留现有聚合根和用户归属模型，只增加 RAG 入库所需的最小字段或表：

- `knowledge_sources` 扩充文件对象键、原始 MIME、获取状态、授权说明、失败码和最新处理时间。
- `knowledge_items` 继续作为可检索切片，增加切片序号、字符范围、审核备注、确定性的 `searchable_text` 和独立 `enabled` 状态；停用后立即退出生产检索，但保留历史引用。
- 数据库启用 `pg_trgm`，为切片标题和 `searchable_text` 建立 GIN trigram 索引；保留现有全文索引用于空格词组和英文内容。
- 新增知识入库任务记录，用于追踪 queued/fetching/parsing/tagging/pending_review/failed，不把处理状态伪装成 AI run。
- 任何新增 actor 归属复合外键继续使用可延迟约束，确保游客合并事务可执行。
- 旧报告、AI run 和 retrieval 快照继续保持不可变来源关系，不通过更新历史记录实现新版本。

具体迁移必须是增量迁移，不修改已提交迁移文件；历史行先安全回填，再增加非空约束或校验约束。

## 8. 错误处理与恢复

- DeepSeek 未配置：提交前返回明确配置错误，不创建假结果。
- DeepSeek 超时、限流或结构失败：AI run 进入 failed，业务会话解除 processing 锁，页面保留输入并提供重试。
- RAG 无命中：继续生成用户资料型建议，并显示无案例依据。
- URL 受限或抓取失败：保留来源草稿、失败码和重试入口；不绕过登录墙。
- 文件解析失败：保留原文件和失败状态，允许重新解析或改为手动文本。
- OCR 缺字段：返回确认页要求用户补齐，不进入报告生成。
- 重复提交：使用客户端 ID、业务版本和幂等键返回同一结果，内容变化则明确冲突。
- 页面刷新：从数据库读取会话、AI run、报告和任务状态，不依赖客户端内存。
- 离线：只保存允许离线的表单草稿；AI 和审核操作明确要求联网。

## 9. 分阶段实施

### 子项目 A：手机前台视觉与闭环深化

- 建立视觉令牌、图标映射、图表和共享状态组件。
- 按工作台 → 工具箱 → 定位 → 创作 → 复盘 → 任务/素材/报告 → 我的顺序升级全部手机页面。
- 补齐缺失的真实读取、写入、恢复和跨页面返回路径。
- 每个页面完成后独立通过组件测试、服务测试和手机尺寸验证。

### 子项目 B：RAG 入库与桌面运营后台

- 增量扩充数据模型和入库状态。
- 实现 URL/文件/文本资料提交、安全获取、解析、切片、标签和审核。
- 完成来源、切片、审核、检索试验、规则、AI 任务和异常后台。
- 接入现有生产检索和引用快照，不重写已经验证的 AI 生成链路。

### 子项目 C：数据、埋点与发布验收

- 将现有埋点事件映射到定位确认、任务保存、复盘行动、任务完成和数据获取流程。
- 补齐真实周期数据和复盘报告指标展示。
- 完成游客与注册用户端到端流程、响应式视觉回归、健康检查和生产构建。

三个子项目依次交付，每个子项目结束时产品都保持可运行；不在一个未验证的大提交中同时重写所有模块。

## 10. 测试与验收

### 10.1 功能验收

- 游客可以完成定位、创作、复盘和任务闭环，注册后数据正确合并。
- 页面刷新后可以恢复定位访谈、AI 处理、报告和任务状态。
- 真实 DeepSeek 成功时持久化结构化结果；失败时显示可恢复错误。
- RAG 只返回双重审核通过的生产资料，引用可追溯到来源和内容版本。
- 固定审核资料建立检索回归集：每条查询必须召回预期切片；待审核、拒绝、停用、Demo 或非生产资料在所有查询中均不得出现。
- URL、文件、文本入库均可完成待审核流程；受限链接和解析失败有明确状态。
- OCR 数据必须经用户确认后才能进入复盘报告。
- 报告建议可以选择性写入任务中心，并且重复提交不产生重复任务。

### 10.2 视觉验收

- 360×800、390×844、412×915 无横向滚动、内容遮挡、底栏覆盖或超大模块。
- 1280×720 与 1440×900 后台表格、筛选、详情和审核操作完整可见。
- 手机列表摘要最多两行；长模型输出不会撑大列表卡片。
- 每个功能模块有统一图标，选中和状态颜色符合语义。
- 页面只有一个主操作，焦点、按压、禁用、加载、空和错误状态完整。

### 10.3 工程验收

- 数据库迁移从当前已提交版本顺序执行成功，迁移测试覆盖历史数据回填。
- 单元测试、服务层测试、真实 PostgreSQL 集成测试和 Playwright 端到端测试通过。
- ESLint、TypeScript、Next.js 生产构建和 worker 构建通过。
- 健康检查覆盖网页、数据库、worker 和私有存储。
- DeepSeek 密钥、邮件密钥和存储密钥不进入浏览器、日志、快照或 Git。

## 11. 本轮不做

- 第三方平台 OAuth、自动发布和未经授权的竞品抓取。
- 支付、套餐、订单和会员权益。
- 强依赖外部 embedding 服务的向量检索。
- 把内部示例、估算数据或人工辅助内测写成正式上线结果。
- 桌面端用户产品专属布局；桌面端只用于运营后台和手机画板居中预览。

## 12. 成功定义

用户在手机上能明确知道「我适合做什么、这次做什么、发布后哪里需要调整、下一步行动是什么」，并且每个 AI 结论都能区分个人资料、确认数据和审核知识依据。管理员能在桌面后台安全地把公开或授权资料变成可审核、可检索、可引用的知识，而不依赖手工改数据库或伪造案例。
