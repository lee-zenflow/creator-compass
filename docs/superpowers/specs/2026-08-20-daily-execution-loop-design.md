# Creator Compass 日常执行闭环设计

日期：2026-08-20
状态：待用户确认书面规格

## 1. 目标

把“定位、创作、复盘生成任务”之后的记录层补成可以每天使用的执行闭环。用户应能快速判断今天做什么、调整顺序、批量处理、找到任务依据，并知道素材和报告当前处于什么真实状态。

本轮不引入周期任务、第三方日历、系统推送、邮件提醒或平台自动同步。计划日期只驱动应用内的今日、逾期和未来状态，避免把尚未接入的能力伪装成可用功能。

## 2. 方案选择

采用“复用现有领域模型的日常执行闭环”，不做仅换皮的界面优化，也不扩展为完整项目管理系统。

理由：任务已经具备计划日期、状态、优先级、顺序和来源版本；素材已经具备来源与创作引用关系；报告已经具备类型、状态、不可变版本和 AI 来源信息。优先把这些真实数据变成可操作界面，可以在较小范围内显著提升可用性，也不会引入新的基础设施。

## 3. 信息架构与界面

### 3.1 任务中心

任务中心保持 390px 紧凑移动布局，卡片目标高度约 84px，不使用大面积看板或多列布局。

顶部提供两组紧凑筛选：

- 时间：今天、本周、全部。
- 状态：待处理、进行中、已完成。

任务卡显示：标题、计划日期、预计用时、状态、优先级、来源类型和来源入口。日期状态由服务端依据计划日期派生：逾期、今天、未来；已完成任务不显示逾期警告。

单条操作包括：开始、完成、恢复和查看详情。进入批量模式后，用户可选择最多 50 条当前可见任务并批量标记完成或恢复。批量操作使用底部固定操作栏，不常驻新模块。

排序使用移动端可靠的“上移/下移”操作，并保留明显的排序把手视觉；不首发依赖拖拽手势。顺序按计划日期分组持久化，同一日期内可调整，不能通过排序偷偷改变计划日期。键盘与读屏用户可以完成同样操作。

### 3.2 素材库

素材列表继续使用约 64px 的紧凑记录行，新增：

- 名称与摘要搜索。
- 真实来源与保存日期。
- 当前活跃引用次数。
- 最近一次关联的创作标题与入口；无关联时明确显示“尚未用于创作”。

素材编辑与删除继续使用现有服务。正在被未归档创作引用的素材禁止删除，并显示具体引用数量；不会静默解除关联。新增素材表单保持默认折叠。

### 3.3 报告记录

报告列表保持定位、创作、复盘筛选，并增加当前状态与归档筛选。报告详情展示：

- 报告类型、标题、摘要和更新时间。
- 每个版本的版本号、状态、创建时间、生成方式（AI 或手动）。
- AI 版本的模型信息、引用依据数量和真实业务详情入口。
- 手动版本的父版本关系。

引用内容仍通过现有 CitationView 边界展示，不暴露内部 itemId、sourceId、对象键或检索分数。

报告失败恢复不新增通用假重试按钮。只有当最新版本关联的 AI run 确实失败且对应领域已有真实恢复动作时，才显示“返回原流程重试”；否则只显示固定失败说明和返回入口。

用户可归档或恢复报告。归档只更新报告聚合根状态，不删除版本、任务、引用或来源快照。

## 4. 领域和数据设计

### 4.1 任务

复用现有 `tasks.status`、`plannedDate`、`priority` 和 `sortOrder`，不新增表。

新增领域操作：

- `startTask(actor, taskId)`：pending → in_progress。
- `batchUpdateTaskStatus(actor, taskIds, targetStatus)`：最多 50 条，事务内锁定并验证全部属于当前 actor，任一无效则整批不写。
- `moveTask(actor, taskId, direction)`：只在同一计划日期的当前未删除任务集合中交换顺序，事务内锁定相关记录。

允许的状态转换固定为：pending → in_progress/completed、in_progress → completed、completed → pending。批量完成只接受 pending、in_progress 或已经处于 completed 的幂等重试；批量恢复只接受 completed 或已经处于 pending 的幂等重试。目标状态相同的任务保持不变且不重复记录事件。`dismissed` 不参与本轮批量和排序操作。

完成、恢复和批量完成继续记录现有分析事件，但幂等重试不得重复记录。

### 4.2 素材

不修改素材写模型。新增只读投影：

```ts
type MaterialUsageSummary = {
  activeReferenceCount: number;
  latestCreation: null | {
    projectId: string;
    title: string;
    updatedAt: Date;
  };
};
```

查询必须同时校验素材、引用和创作项目属于同一 actor。列表搜索继续在数据库执行，并限制查询长度与结果数量。

### 4.3 报告

复用报告聚合根与三类不可变版本表。扩展只读记录，返回生成方式、创建时间、父版本、领域实体 ID、AI run 状态和经过清洗的引用视图。

新增 `archiveReport(actor, reportId)` 与 `restoreReport(actor, reportId)`。归档状态不级联修改版本；详情仍可读取，默认列表隐藏归档报告，归档筛选可查看。恢复时把聚合根状态同步为最新不可变版本的真实状态，而不是一律写成 ready。

## 5. 请求和状态流

所有写操作通过 Server Action 调用领域服务：

1. 从服务端 cookie/session 解析 actor，不接收客户端 owner ID。
2. 使用 Zod 校验任务 ID、报告 ID、批量数量、目标状态和排序方向。
3. 在事务内锁定并校验目标记录。
4. 完成写入后重新验证受影响页面。
5. 返回固定 notice code；页面映射为安全、可恢复的中文文案。

界面不使用定时递增进度或本地假成功。Server Action 未完成前控件进入 pending 状态；失败后保留用户当前筛选和选择，允许重试。

## 6. 异常与安全边界

- 跨用户任务、素材引用或报告一律按不存在处理。
- 批量请求包含一个无效或越权 ID 时整批回滚。
- 同一批次重复 ID 在服务端去重；空集合拒绝。
- 同一日期排序并发时锁定参与记录，避免重复或丢失顺序。
- 归档报告不能删除历史版本，也不能让已生成任务失去来源入口。
- 素材使用统计不得暴露其他用户的项目标题或数量。
- 失败文案只使用固定码，不透传数据库、队列或模型错误。

## 7. 视觉与无障碍

- 继续使用现有 Compass Instrument 色板、图标体系和 6/8px 圆角。
- 所有点击区域至少 42px；修正现有紧凑分段控件的 30px 高度。
- 逾期使用低饱和警示色和文字，不只依赖颜色。
- 批量模式与普通模式保持同一信息密度，不扩大任务卡。
- 状态变化提供可读文本；图标仅作辅助。
- 支持 360×800、390×844、412×915，不允许横向溢出。
- 遵守 `prefers-reduced-motion`，只使用 transform/opacity 的短反馈，不增加连续动画。

## 8. 测试与验收

严格按 RED → GREEN 实施。

领域测试：

- 开始、完成、恢复状态转换与非法转换。
- 批量最多 50 条、去重、原子回滚、跨 actor 零写入。
- 同日期排序持久化、首尾边界、并发锁定。
- 素材引用数量和最近创作均为 owner-safe。
- 报告归档保留版本和任务来源。
- 失败恢复只在真实 failed AI run 时出现。

界面测试：

- 筛选参数可刷新恢复。
- 批量操作栏只在选择后出现。
- 任务、素材、报告列表不因长文案撑大。
- 所有真实入口可导航，无 `#` 或装饰性按钮。
- 360、390、412 三视口无重叠、截断和横向滚动。

发布验证：

- 相关定向测试、全量 Vitest、typecheck、lint、Next build、worker build 全部通过。
- 有隔离 PostgreSQL、邮件和对象存储时，运行真实 Playwright 闭环；缺少基础设施时必须明确报告为未验证，不能用 skipped 代替通过。

## 9. 明确不做

- 第三方日历同步。
- 系统通知、浏览器推送或邮件提醒。
- 周期任务、子任务依赖、甘特图、看板和团队协作。
- 自动平台数据同步或 OAuth。
- 删除报告版本、检索快照或任务来源证据。

这些能力需要新的调度、授权、通知或协作基础设施，不应在本轮以假入口出现。
