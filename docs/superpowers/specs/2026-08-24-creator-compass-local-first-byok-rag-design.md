# Creator Compass 本地单用户、BYOK 与语义 RAG 完整化设计

日期：2026-08-24  
状态：已与用户逐项确认，待实现  
适用仓库：`creator-compass`

## 1. 背景与目标

Creator Compass 已具备「0-1 IP 定位 → 事前创作 → 数据复盘 → 下一轮任务」的移动端主流程、报告版本、任务、素材、审核知识检索及桌面运营后台。本轮不推倒重做，也不改变原 Figma 的页面顺序和紧凑手机造型，而是在现有项目上完成本地优先改造，补齐真实 BYOK、语义 RAG、发布内容记录、备份恢复和本地发布能力。

正式产品面向安装在个人 Windows 电脑上的单一 Owner。前台保持 390×844 的手机比例界面，知识运营后台保持桌面布局；所有服务仅监听本机，不提供公网部署或局域网手机访问。

完成后的主闭环为：

```text
定位访谈 → 定位候选 → 定位确认 → 定位任务
→ 事前创作 → 创作方案 → 执行任务 → 标记内容已发布
→ 内容记录 → 数据快照 / 本地 OCR → 复盘报告
→ 改进任务 → 下一轮创作
```

## 2. 已确认的产品边界

### 2.1 必须保留

- 原 Figma 的四个底部导航：工作台、工具箱、任务、我的。
- 工具箱五个入口：IP 定位、事前创作、数据复盘、素材库、报告记录。
- 定位、创作、复盘的报告版本、任务来源、素材引用和证据追溯。
- 390px 紧凑手机画板、64px 列表、84px 任务卡和约 148px 定位候选。
- 桌面知识运营后台及来源、切片、审核、规则、提示词、AI 任务和检索诊断。
- 每个一级模块、报告类型、任务来源、知识状态和后台菜单的稳定图标。

### 2.2 正式删除或不再承诺

- 游客账户、30 天游客数据、注册后合并。
- 邮箱注册、邮箱验证、邮件找回和邮件提醒。
- 开放注册、多用户、团队协作和租户能力。
- 平台 OAuth、自动同步、平台令牌和自动发布。
- 套餐、支付、订单和订阅。
- 网页自动抓取、URL 入库和登录墙绕过。
- 扫描版 PDF 的批量文档 OCR。
- 手机连接电脑、局域网访问和公网部署。
- 自动发送遥测、第三方统计 SDK 和外部错误跟踪。

### 2.3 真实能力表述

- “平台账号”改名为“发布平台”，只记录平台、账号名称与内容偏好，不暗示授权连接。
- 任务提醒只存在于应用内的今日、逾期、未来和当前步骤，不宣称系统通知、推送或日历同步。
- 向量服务不可用时明确显示关键词降级，不把关键词检索伪装成语义 RAG。
- 没有知识命中时允许基于用户输入生成，但必须写明暂无知识库依据。
- GitHub 不包含用户的简历、作品集、课程资料、私人文件、真实知识库和任何 API Key。

## 3. 方案选择

采用方案 A：在现有项目上渐进式本地化改造。

未采用的方案：

1. 重新创建本地版项目：会丢失已完成的业务服务、测试、视觉约束和版本追溯，迁移风险高。
2. 同时维护在线 SaaS 与本地模式：认证、存储、隐私、测试和发布复杂度接近翻倍，不符合当前单机产品目标。

## 4. 最终运行架构

```text
电脑浏览器
    │ 127.0.0.1
    ▼
Creator Compass App
    ├── PostgreSQL + pgvector
    ├── 私有文件卷
    ├── 后台 Worker
    ├── 本地中文向量服务
    └── DeepSeek API（仅用户主动生成时访问）
```

Docker Compose 只保留：

- `app`：Next.js 页面与 API。
- `worker`：AI 运行、知识入库、快照、备份和受控后台任务。
- `postgres`：PostgreSQL 与 pgvector，承载业务数据、队列、审计和向量。
- `embedding`：纯 CPU 中文向量服务。
- 私有文件卷、模型缓存卷、密钥卷和数据库卷。

移除 Mailpit、SMTP、MinIO、S3 和不必要的独立缓存服务。只有网页端口映射到 `127.0.0.1`，其他容器不暴露宿主机端口。

本地向量模型固定为 `BAAI/bge-small-zh-v1.5`，使用 512 维归一化向量。查询使用模型规定的中文检索指令，文档片段不添加查询指令。模型缓存保存在独立 Docker 卷，首次启动下载；有缓存后可离线运行。首版必须支持纯 CPU，不要求独立显卡。

## 5. 本地账户与初始化

### 5.1 首次初始化

- 数据库没有 Owner 时，首页进入本地初始化。
- 用户设置本地用户名与密码，不要求邮箱或手机号。
- 初始化在事务中完成，确保只创建一个 Owner。
- 初始化成功后永久关闭公开注册、游客入口和第二账户创建。
- 系统生成一次性恢复码，只展示一次；数据库只保存带盐哈希。

### 5.2 登录与恢复

- 登录使用用户名和密码。
- 忘记密码使用未消费的恢复码。
- 恢复码使用后立即失效。
- Owner 登录后可以重新生成恢复码，旧码全部作废。
- 重置密码不删除业务数据，也不暴露 DeepSeek Key。

### 5.3 旧数据迁移

- 不自动删除旧用户或游客数据。
- 没有正式用户时进入首次初始化。
- 只有一个正式用户时，迁移助手允许将其转换为本地 Owner，并设置新用户名、密码与恢复码。
- 存在多个用户或游客数据时，启动迁移助手；用户先导出，再明确选择保留对象。系统不能自行合并或删除。
- 游客字段只有在迁移完成且数据归属确认后才允许清理。

## 6. DeepSeek BYOK

### 6.1 固定供应商和模型

- 只支持 DeepSeek。
- 模型固定为 `deepseek-v4-flash`。
- 不允许用户填写任意 Base URL、模型名、温度或底层参数。
- 未配置有效 Key 时，定位、创作、复盘和可选知识标签增强的生成操作全部阻止；其他本地功能继续可用。

### 6.2 Key 安全

- 首次启动自动生成 256 位主密钥并写入 Docker 私有密钥卷。
- DeepSeek Key 采用版本化 AES-256-GCM 密文，每次加密使用独立随机 IV。
- 前端只接收“已配置”、末四位、最近测试时间和状态。
- 支持测试、替换和撤销。
- Key 不得进入浏览器持久化、日志、队列载荷、报告、引用、埋点、普通数据导出或备份。
- Worker 仅在调用前短暂解密，调用完成后不保留明文引用。
- 删除 Key 保留全部历史定位、创作、复盘、任务、素材和报告，只阻止新请求与重试。

### 6.3 隐私披露

- 配置 Key 时展示一次总隐私同意。
- 每个 AI 入口在生成按钮上方常驻展示本次将发送的数据类别、资料名称和片段数量。
- 用户可展开查看具体内容，并取消可选素材或知识片段。
- 核心输入不能取消；缺少核心输入时不能生成。
- 不发送密码、API Key、用户名、原始对象地址、其他用户数据或未经允许的知识片段。
- 每次点击生成即视为确认当前可见披露，不重复弹出二次确认窗口。

### 6.4 用量与失败

- 每次运行记录输入和输出 Token，页面展示单次与当月汇总，不估算人民币成本。
- 模型请求发出前的队列错误允许安全自动恢复。
- 模型请求已经发出后不自动重复调用，由用户手动重试，避免重复计费。
- Key 无效、余额不足、限流、超时、模型拒绝和网络失败使用安全错误类型；保留用户输入。

## 7. 本地知识库与语义 RAG

### 7.1 导入边界

- 支持带文本层的 PDF、DOCX、TXT 和粘贴文本。
- 不支持 URL 抓取。
- 扫描版 PDF 若没有可用文字，明确提示并停止，不写入空白或乱码切片。
- 文件解析、分块、向量化和入库不依赖 DeepSeek。
- 用户导入时手动选择平台、内容类型、基础标签和授权说明。
- “AI 补充摘要与标签”是可选操作，必须显示将发送的片段，结果仍需审核。

### 7.2 分块和向量

- 正文标准化后按 300–800 字分块，固定 100 字重叠，并保存原文字符坐标。
- 每个切片保存内容哈希、来源版本、切片序号、质量状态、向量模型、向量版本和 512 维向量。
- 重新向量化生成新向量版本，不静默修改历史报告的引用快照。
- 向量服务不可用时，入库任务保留状态并可继续；已有资料使用关键词降级检索。

### 7.3 审核和发送权限

- 每个来源拥有独立“允许发送给 DeepSeek”开关，默认关闭。
- 导入后展示文档质量、切片数、重复率和异常片段。
- 用户必须检查开头、中间、结尾和全部异常片段。
- 无异常时允许批量批准剩余片段。
- 空白、过短、重复或乱码片段不能批量通过。
- 只有来源批准、切片批准且允许发送三个条件全部满足，片段才可进入 AI 生成检索。
- 未允许发送的资料仍可本地搜索。
- 停用或删除来源后，新请求不能命中；历史报告引用仍保留来源版本与内容哈希。

### 7.4 混合检索

检索顺序：

1. 平台、内容类型、审核状态、启用状态和发送权限等硬过滤。
2. PostgreSQL 全文、标签、规范化关键词和三元组检索。
3. pgvector 余弦语义检索。
4. 使用排名融合合并两路结果，避免依赖难解释的任意权重。
5. 最多选择 8 个片段，同一来源最多 3 个。
6. 保存真实命中片段、来源版本、分数、检索模式和降级状态。

向量服务异常时明确降级为 `deterministic_text`；没有命中时明确标记 `no_knowledge_hit`。两种状态都不能伪装为完整语义 RAG。

## 8. 完整业务闭环

### 8.1 IP 定位

- 定位记录 → AI 访谈 → 画像完整度 → 三个候选 → 候选详情 → 用户确认 → 定位任务。
- 候选与最终报告区分个人输入、历史资料和审核知识依据。
- 用户确认后追加定位报告版本和个人创作档案版本，不覆盖历史。

### 8.2 事前创作

- 填写需求 → 选择个人素材 → 读取定位与历史 → 本地混合检索 → 生成方案 → 人工编辑 → 执行任务。
- 方案区分个人档案、素材、历史结论和知识依据。
- 任务保存使用来源报告版本和稳定任务标识保证幂等。

### 8.3 内容记录

新增 `published_contents`，但不增加一级导航：

- 创作方案或相关任务完成后提供“标记为已发布”。
- 保存来源创作方案及版本、发布平台、最终标题、发布时间和可选内容链接。
- 工作台识别已发布但未复盘的内容，并将其作为真实下一步。
- 复盘页可以选择已有内容并自动带入平台、标题和发布时间。
- 允许新增外部创作内容，用于复盘未经过本产品生成的作品。
- 同一内容可以追加多次数据快照，但对应同一条连续复盘记录。

### 8.4 数据复盘

- 选择内容 → 手动数据或浏览器本地 OCR → 逐项确认 → 程序计算 → AI 复盘 → 人工调整 → 改进任务。
- 原截图默认不上传；只有用户主动选择保留时才写入私有文件卷。
- 复盘报告保存确认数据、计算指标、结论、引用、内容记录和行动任务版本。

### 8.5 日常执行

- 任务中心继续提供今日、本周、全部、状态筛选、开始、完成、恢复、同日排序和原子批量操作。
- 工作台只突出一个真实下一步，并展示少量任务、最近报告和闭环位置。
- 任务可以返回定位、创作或复盘来源及版本。
- 任务提醒仅为应用内日期与状态，不提供推送或邮件。

## 9. 页面与视觉

### 9.1 前台结构

- 首次使用：产品介绍、本地初始化、登录、恢复码重置。
- 工作台：当前行动、真实指标、微型趋势、近期任务、最近报告和闭环位置。
- 工具箱：IP 定位、事前创作、数据复盘、素材库、报告记录。
- 任务：今日、本周、全部和真实状态操作。
- 我的：发布平台、个人档案、报告、DeepSeek 设置、备份恢复、本地隐私、版本更新和运营管理。

### 9.2 桌面后台

- 知识概览、资料导入、来源与切片审核、混合检索试验台。
- 平台规则、提示词版本、AI 运行、失败任务和本地漏斗。
- 备份、系统健康和版本状态。

### 9.3 视觉边界

- 主画板 390×844，同时验证 360×800、390×844 和 412×915。
- 列表约 64px、任务约 84px、定位候选约 148px、主要控件约 42px。
- 使用黑白灰、低饱和青色和稳定的小面积模块识别色。
- 通过细坐标线、步骤编号、局部深色行动区、微型趋势线和短促状态脉冲形成“指南针仪表”品牌感。
- 禁止大面积渐变、玻璃拟态、厚阴影、装饰性星星、通用魔法图标和放大卡片。
- 动效约 160–220ms，只用于状态变化，并支持减少动态效果。
- 每页包含真实的加载、空、处理中、失败、降级、成功和离线状态。

## 10. 离线与降级

- 断网时仍可查看和编辑档案、任务、素材、报告与知识库。
- 断网时仍可完成任务、手动录入复盘数据、使用本地 OCR 和本地搜索。
- 新的 DeepSeek 生成明确标记“需要网络连接”，保留输入，联网后由用户手动重试。
- 不后台偷偷发送，也不把离线模板包装为 AI 结果。

## 11. 备份、快照、删除与更新

### 11.1 自动快照

- 每天首次启动且数据变化时创建一次。
- 保留最近 7 份。
- 包含数据库、私有文件和一致性清单。
- 使用本地主密钥加密，只用于当前设备恢复。
- 恢复前先保存当前状态；失败时回滚。

### 11.2 便携加密备份

- 用户必须设置独立备份密码。
- 使用 `scrypt` 派生密钥并采用 AES-256-GCM 加密。
- 包含业务数据、知识文件、报告、任务、素材、审核记录和本地统计。
- 不包含 DeepSeek Key、主密钥、登录密码和恢复码。
- 恢复时先校验版本、哈希和完整性，再进入维护模式执行。
- 恢复后必须重新填写 DeepSeek Key。

### 11.3 恢复出厂状态

- “删除账号”改为“恢复出厂状态”。
- 必须输入当前密码、指定确认文字并二次确认。
- 删除 Owner、DeepSeek Key、全部业务数据、知识文件、向量、日志和自动快照。
- 保留程序文件和已下载向量模型。
- 完成后返回首次初始化。

### 11.4 版本更新

- 设置页显示当前版本，只有用户主动点击时才检查 GitHub Release。
- 不后台轮询、不自动下载。
- 更新脚本先创建快照，再拉取固定 Tag 或固定镜像并执行迁移。
- 更新失败恢复旧版本和更新前快照。
- 开发分支不能作为正式更新源。

## 12. 本地埋点与隐私

- 产品事件只写入本地数据库，不接入第三方统计或外部遥测。
- 后台提供定位确认、任务保存、复盘转任务、任务完成、数据获取和失败分析。
- 默认保留最近 90 天，可由用户立即清空。
- 便携备份可以包含本地统计；恢复出厂时全部删除。
- README 明确声明“无外部遥测”。

## 13. 异常与恢复

- 所有异常保留用户输入并显示真实状态。
- 未配置 Key、Key 无效、余额不足、限流、模型拒绝、断网和超时均有独立安全错误。
- 文档解析失败保留来源记录和失败原因，不生成垃圾切片。
- Worker 重启从数据库恢复未完成任务。
- 向量服务异常进入明确的关键词降级模式。
- 备份密码错误、归档被篡改或版本不兼容时，在修改现有数据前终止。
- 不使用假成功、无限重试、静态示例或 skipped 测试代替真实通过。

## 14. 测试与完成标准

### 14.1 本地初始化与安全

- 新设备可一键启动并创建唯一 Owner；第二账户创建被拒绝。
- 恢复码可重置密码且只能使用一次。
- Key 配置、测试、替换和撤销可用，完整 Key 不出现在页面、日志、导出或普通数据库查询中。

### 14.2 业务闭环

- 定位、创作、发布内容、复盘和下一轮任务可以连续完成。
- 报告、任务、素材、内容记录和引用均能返回真实来源与版本。
- 重复保存任务、内容和报告不会产生重复记录。

### 14.3 RAG

- 没有 DeepSeek Key 也能完成本地导入、分块、向量化、审核和搜索。
- 混合检索只返回满足审核与发送权限的片段。
- 语义检索、关键词降级和无命中三种状态均有自动化与页面验证。
- 重新向量化不改变旧报告引用快照。

### 14.4 备份与恢复

- 自动快照最多保留 7 份。
- 便携备份可在干净实例恢复全部业务与文件。
- 错误密码、篡改和不兼容版本均被安全阻止。

## 16. 最终成功判断

产品只有在用户能够在本机真实完成以下链路时才算完成：

```text
初始化 Owner
→ 配置并验证自己的 DeepSeek Key
→ 完成定位
→ 生成并编辑创作方案
→ 执行任务并标记内容发布
→ 确认真实数据并生成复盘
→ 保存下一轮行动
→ 导入、审核并使用本地知识
→ 生成加密备份并在干净实例恢复
```

视觉上必须保持原 Figma 的紧凑手机框架，并通过指南针坐标、模块图标、局部数据脉冲和真实状态形成稳定品牌感；功能上必须区分本地事实、DeepSeek 输出、知识依据、关键词降级和待用户确认内容。
