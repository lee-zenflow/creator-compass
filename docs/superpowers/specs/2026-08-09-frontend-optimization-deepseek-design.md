# Creator Compass 全前台优化与 DeepSeek 接入设计

日期：2026-08-09

## 目标

在不推翻现有产品架构和业务闭环的前提下，按照用户已有 Figma 造型统一优化全部前台页面。重点解决模块过大、留白过多、信息层级松散、列表内容撑高和下一步操作不明确的问题，同时把本机 AI 从体验适配器切换为真实 DeepSeek `deepseek-chat`。

## 设计原则

- 产品继续采用 390px 移动端画板，不扩展为桌面仪表盘。
- 保留黑白灰、细边框、低装饰的 Figma 视觉语言，不引入渐变、厚阴影、玻璃效果或大圆角卡片。
- 48px 顶栏、62px 底栏、42px 主按钮保持不变。
- 页面左右间距 15px；主要模块间距 8–10px；圆角 6–8px。
- 普通列表行控制在 46–64px；任务预览约 84px；定位候选约 148px。
- 列表态长内容最多展示 1–2 行，完整信息进入详情页。
- 卡片只用于独立可操作对象。普通说明、状态和分组优先使用分隔线或紧凑列表。
- 每页只保留一个主操作；次操作使用文字按钮或轻按钮。
- 空状态使用短文案和直接行动，不使用占据大面积的虚线框。

## 页面范围与顺序

### 第一阶段：公共系统与工作台

- 收敛公共间距、空状态、分组标题、按钮、表单、列表和状态反馈。
- 工作台首屏优先呈现当前账号、核心状态和明确的下一步行动。
- 数据、任务和报告保持真实空状态，不填充演示数字。

### 第二阶段：定位流程

- 定位记录、访谈、生成状态、三候选、候选详情、确认和任务预览使用同一紧凑节奏。
- 访谈页控制可见消息数量，输入区固定且不挤压正文。
- 生成状态只显示数据库记录的真实状态，不展示虚构百分比或预计时间。
- 候选列表只展示摘要；详情页展示完整依据、风险和任务。

### 第三阶段：创作与素材

- 创作需求、素材选择、内容方案和任务写入保持连续返回路径。
- 素材列表默认紧凑展示；新增或编辑表单按需出现，不常驻占据首屏。
- 内容方案按文章、视频和短文类型展示必要字段，不堆叠无关模块。

### 第四阶段：复盘、报告与任务

- 复盘输入、OCR 确认、报告和改进任务保持同一数据来源说明。
- 报告列表显示类型、状态、版本和短摘要；完整结论进入详情页。
- 任务列表支持今日、本周、全部，完成操作使用真实服务端状态。

### 第五阶段：我的与身份页面

- 个人档案、账号标签、提醒、数据导出、账号删除、登录和注册统一视觉密度。
- 危险操作保持单独确认，不因视觉简化而削弱安全提示。

## DeepSeek 接入

- API 密钥只保存在本机 `.env.local`，不得进入源代码、日志、测试快照或 Git。
- 本机 AI 配置切换为 `AI_ADAPTER=deepseek`、`DEEPSEEK_MODEL=deepseek-chat`。
- 网页只提交业务输入和幂等标识，密钥只由服务端工作进程读取。
- 模型输出继续经过现有 Zod 结构校验、引用白名单、用户归属校验和事务持久化。
- 未配置、超时、限流、结构校验失败和最终失败均显示明确可恢复状态，不回退到伪造内容。

## 数据与交互边界

- 不修改已经稳定的聚合根、版本记录和用户归属模型，页面通过现有服务层读写。
- 页面刷新后从数据库恢复任务、报告和 AI run 状态，不依赖客户端假状态。
- 列表和详情使用同一条真实记录；URL 中的候选、任务和报告标识必须再次由服务端校验。
- 不接入平台授权、自动抓取、支付或短信，不扩大本轮范围。

## 错误处理

- 表单错误就近显示，保留用户输入。
- AI 处理中显示可离开页面的真实等待状态；失败后提供重新提交入口。
- 网络或服务端失败不得把页面切到成功状态。
- 长文本、缺少数据和空列表均需保持布局稳定，不撑破 390px 画板。

## 验收标准

- 390×844、360×800、412×915 均无横向滚动、遮挡或超大模块。
- 工作台到定位、创作、复盘、任务和档案的主要路径可完成并可刷新恢复。
- 列表卡片高度受控，长文本有截断，详情内容完整可读。
- DeepSeek 密钥未进入 Git；真实调用成功或以明确失败状态结束。
- 数据库、worker、私有存储和网页健康检查全部通过。
- 单元测试、真实 PostgreSQL 集成测试、类型检查、代码检查和生产构建全部通过。

## 不在本轮范围

- 桌面端专属布局。
- 第三方平台 OAuth、数据自动同步和自动发布。
- 付费、套餐和订单系统。
- 将内部示例或本地体验结果包装成真实案例。
